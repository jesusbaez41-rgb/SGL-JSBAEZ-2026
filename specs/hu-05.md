# HU-COM-05 — Administración de grupos y membresías con Samba AD

**Código:** HU-COM-05  
**Módulo/Épica:** Gestión de Grupos y Permisos  
**Entorno:** Plataforma Web + Servidor Central (Backend + Samba AD + PostgreSQL)  
**Prioridad:** Must Have  
**Estimación:** 8 SP  
**Estado:** Implementada  
**Fecha:** 2026-11-11

## 1. Objetivo

Permitir que el Administrador Académico y el Administrador Técnico registren,
modifiquen y eliminen grupos de estudiantes, los sincronicen con Samba AD y
asignen o remuevan estudiantes y docentes a los grupos, para organizar
comisiones, vincular alumnos con asignaturas y habilitar el monitoreo docente.

**Como** Administrador Académico / Técnico  
**Quiero** registrar, modificar y eliminar grupos de estudiantes,
sincronizarlos con Samba AD y asignar o remover estudiantes y docentes a grupos  
**Para** organizar comisiones, vincular alumnos con asignaturas y permitir que
los docentes monitoreen sus cursos.

## 2. Alcance

Incluye:

- CRUD de grupos (código y descripción).
- Validación de código único global en PostgreSQL y Samba AD.
- Creación, modificación y eliminación del grupo en Samba AD.
- Persistencia de `samba_sid` y `samba_dn` en PostgreSQL.
- Asignación y remoción de estudiantes al grupo, con sincronización de la
  membresía en Samba AD.
- Asignación y remoción de docentes al grupo para monitoreo, solo en
  PostgreSQL.
- Eliminación segura: se elimina el grupo y sus relaciones, pero **no** las
  cuentas de usuario (RN-014).
- Auditoría de altas, modificaciones, eliminaciones y cambios de membresía
  (RN-010).

No incluye:

- CRUD de usuarios (HU-COM-02).
- Autenticación web (HU-COM-14).
- Monitoreo en tiempo real/KVM (HU-COM-04/RN-017).
- Sincronización automática de grupos desde Samba AD hacia PostgreSQL.

## 4. API

| Método | Ruta | Permiso | Descripción |
|---|---|---|---|
| `GET` | `/api/groups` | `groups:read` | Lista grupos con cantidad de estudiantes y docentes |
| `GET` | `/api/groups/:id` | `groups:read` | Detalle del grupo con estudiantes y docentes |
| `POST` | `/api/groups` | `groups:manage` | Crea un grupo en Samba AD y PostgreSQL |
| `PATCH` | `/api/groups/:id` | `groups:manage` | Actualiza la descripción del grupo |
| `DELETE` | `/api/groups/:id` | `groups:manage` | Elimina el grupo y sus relaciones, sin borrar usuarios |
| `POST` | `/api/groups/:id/members` | `groups:manage` | Agrega un estudiante al grupo |
| `DELETE` | `/api/groups/:id/members/:userId` | `groups:manage` | Remueve un estudiante del grupo |
| `POST` | `/api/groups/:id/teachers` | `groups:manage` | Asigna un docente al grupo para monitoreo |
| `DELETE` | `/api/groups/:id/teachers/:userId` | `groups:manage` | Remueve la asignación del docente |

### Ejemplo de creación

```json
POST /api/groups
{
  "codigo": "GRP-2B",
  "descripcion": "Segundo año, comisión B"
}
```

### Ejemplo de alta de estudiante

```json
POST /api/groups/<grupo-id>/members
{
  "usuario_id": "<usuario-id>"
}
```

## 5. Modelo de datos

No se agregan tablas: se reutilizan las existentes.

### `grupo`

- `id` UUID.
- `codigo` único, obligatorio.
- `descripcion`.
- `samba_sid`.
- `samba_dn`.
- `created_at`.

### `membresia_grupo`

- `usuario_id` → `usuario.id` (`ON DELETE CASCADE`).
- `grupo_id` → `grupo.id` (`ON DELETE CASCADE`).
- `fecha_asignacion`.
- `activa`.
- Restricción única `(usuario_id, grupo_id)`.

### `asignacion_docente`

- `docente_id` → `usuario.id` (`ON DELETE CASCADE`).
- `grupo_id` → `grupo.id` (`ON DELETE CASCADE`).
- `fecha_asignacion`.
- Restricción única `(docente_id, grupo_id)`.

> **RN-015:** los estudiantes se agregan como miembros del grupo en Samba AD.
> Los docentes **no** se agregan como miembros del grupo en Samba AD; su
> asignación se guarda en `asignacion_docente` para habilitar el monitoreo.

## 6. Operaciones LDAP

Ubicación: `backend/src/modules/auth/ldap.service.js`.

| Función | Operación |
|---|---|
| `findGroupByCode(codigo)` | Búsqueda por `sAMAccountName` |
| `findGroupByDn(dn)` | Búsqueda base por DN |
| `createGroup({ codigo, descripcion })` | `add` de `objectClass=group` |
| `updateGroup(dn, { descripcion })` | `modify` de `description` |
| `deleteGroup(dn)` | `del` del grupo |
| `addGroupMember(groupDn, userDn)` | `modify` add de `member` |
| `removeGroupMember(groupDn, userDn)` | `modify` delete de `member` |

- El grupo se crea bajo `LDAP_GROUPS_DN` (por defecto, el mismo contenedor de
  usuarios).
- El `groupType` se configura como grupo global de seguridad.
- Los errores LDAP se traducen a códigos de dominio (`CODIGO_DUPLICADO_AD`,
  `LDAP_SERVICE_UNAVAILABLE`, etc.).
- Las operaciones de membresía son idempotentes.

## 7. Reglas de negocio

| RN | Impacto |
|---|---|
| RN-010 | Altas, modificaciones, bajas y cambios de membresía se auditan |
| RN-011 | Código de grupo único en PostgreSQL y Samba AD |
| RN-012 | Un estudiante puede pertenecer a varios grupos |
| RN-014 | Al eliminar un grupo no se eliminan usuarios, solo relaciones |
| RN-015 | Solo estudiantes pueden ser miembros; docentes se asignan para monitoreo |
| RN-017 | La asignación docente habilita el monitoreo de sus grupos |

## 8. RBAC

| Permiso | Admin Académico | Admin Técnico | Docente |
|---|---:|---:|---:|
| `groups:read` | ✅ | ✅ | ✅ (solo sus grupos) |
| `groups:manage` | ✅ | ✅ | — |

La HU amplía `groups:read`/`groups:manage` al Administrador Técnico.

## 9. Interfaz

- **Grupos:** listado con código, descripción, cantidad de estudiantes y
  docentes; alta/edición en modal; eliminación con confirmación.
- **Miembros:** modal con dos secciones:
  - Estudiantes: miembros actuales + selector de estudiantes disponibles.
  - Docentes: docentes asignados + selector de docentes disponibles.
- Mensajes de éxito/error y estados de carga.
- El menú lateral muestra **Grupos** según el permiso `groups:read`.
