# HU-COM-04 — Registro y monitoreo de PCs con agente MeshCentral

**Código:** HU-COM-04  
**Módulo/Épica:** Gestión de Infraestructura / Laboratorios y Equipos  
**Entorno:** PC Cliente Windows + Plataforma Web + Servidor Central (Backend + MeshCentral)  
**Prioridad:** Must Have  
**Estimación:** 8 SP  
**Estado:** Implementada (registro automático, consulta y monitoreo)  
**Fecha:** 2026-11-05

## 1. Objetivo

Instalar y registrar el agente MeshCentral en cada PC cliente, y que el backend
consulte a MeshCentral el estado de los equipos para mostrarlo en la plataforma
web, permitiendo administración remota, monitoreo, inventario y supervisión de
disponibilidad de las PCs.

**Como** Administrador Técnico / Docente  
**Quiero** instalar y registrar el agente MeshCentral en cada PC cliente, y que
el backend consulte a MeshCentral el estado de los equipos para mostrarlo en la
plataforma web  
**Para** permitir administración remota, monitoreo, inventario y supervisión de
disponibilidad de las PCs.

## 2. Alcance

Incluye:

- Instalación del agente MeshCentral como servicio de Windows (`LocalSystem`,
  todos los usuarios) y conexión saliente por WSS.
- Obtención de MAC, hostname, IP, estado, último reporte y usuario activo desde
  MeshCentral.
- Registro automático de PCs en el inventario SGL (`equipo`), infiriendo el
  laboratorio por subred (RN-001).
- Consulta de equipos filtrada por laboratorio.
- Sincronización bajo demanda y periódica con MeshCentral.
- Visualización del estado en la plataforma web con actualización automática.
- Manejo controlado de errores: si MeshCentral no responde, el estado mostrado
  es **Desconocido** y el fallo queda registrado.

No incluye:

- Despliegue de aplicaciones o políticas (HU de despliegues).
- KVM/escritorio remoto dentro de la plataforma web (se abre MeshCentral).
- Registro automático de sesiones de estudiante (`sesion_activa`), que
  corresponde a HU-COM-01.
- Gestión de usuarios/grupos (HU-COM-02/HU-COM-14).

## 4. API

| Método | Ruta | Permiso | Descripción |
|---|---|---|---|
| `GET` | `/api/equipment?laboratorio_id=<uuid>` | `equipment:read` | Lista PCs, opcionalmente filtradas por laboratorio. |
| `GET` | `/api/equipment/:id` | `equipment:read` | Consulta una PC y su estado actual. |
| `POST` | `/api/equipment/sync` | `equipment:manage` | Sincroniza/importa PCs desde MeshCentral. Acepta `{ laboratorio_id }` opcional. |
| `POST` | `/api/equipment/:id/refresh` | `equipment:manage` | Refresca una PC; si MeshCentral falla devuelve estado Desconocido. |
| `GET` | `/api/labs` | `labs:read` | Laboratorios con cantidad de equipos. |
| `GET` | `/api/labs/:id` | `labs:read` | Detalle de un laboratorio. |

### Respuesta de sincronización

```json
{
  "data": {
    "creados": 1,
    "actualizados": 3,
    "total": 4,
    "sin_laboratorio": 0,
    "sin_mac": 0,
    "errores": 0,
    "detalle": []
  }
}
```

## 5. Modelo de datos

No se agregan tablas. Se reutilizan:

- `equipo`: `mac_address` único, `hostname` único, `ip_address`,
  `laboratorio_id` obligatorio, `estado`
  (`ENCENDIDO|APAGADO|DESCONOCIDO`), `mesh_agent_id` único, `ultimo_reporte`.
- `laboratorio`: `subred` CIDR usada para inferir el laboratorio de una PC
  nueva.
- `sesion_activa`: usuario activo cuando exista registro de logon.
- `auditoria`: registro de sincronizaciones y refrescos (RN-010).

## 6. Integración con MeshCentral

```text
PC Windows (MeshAgent)
   │  WSS saliente → https://192.168.100.58/mesh/
   ▼
Nginx (sgl-frontend) → MeshCentral (systemd, 4433)
   ▲
   │  meshctrl ListDevices --details --json
Bridge SGL (systemd, 172.18.0.1:4444)
   ▲
   │  GET /devices  (x-api-key)
Backend SGL
   │  sync: upsert en PostgreSQL
   ▼
PostgreSQL → API → UI (Equipos / Laboratorios)
```

El bridge normaliza la respuesta de MeshCentral:

- `node._id` → `nodeid` / `mesh_agent_id`.
- `node.name` → `hostname`.
- `net.netif2[*][*].mac` → `mac_address` (primera interfaz Ethernet no loopback).
- `net.netif2[*][*].address` → `ip_address`.
- `node.users` / `node.lusers` → `usuario_actual`.
- `node.conn` → `estado` (`ENCENDIDO`/`APAGADO`).
- `lastConnect` → `ultimo_reporte`.

## 7. Registro automático

Al sincronizar:

1. Se busca la PC por `mesh_agent_id`, luego por `mac_address` y luego por
   `hostname`.
2. Si existe, se actualizan estado, IP, último reporte y agente.
3. Si no existe y tiene MAC + hostname:
   - se usa el laboratorio indicado en la petición, o
   - se infiere el laboratorio cuya `subred` contiene la IP de la PC.
4. Si no hay laboratorio o MAC, no se crea la PC (RN-001) y se informa en el
   resumen (`sin_laboratorio` / `sin_mac`).
5. Cada sincronización se audita en `auditoria`.

## 8. Actualización periódica

- **Bajo demanda:** `GET /api/equipment` consulta el bridge y devuelve el estado
  actual sin esperar a la BD.
- **Periódica:** el backend ejecuta un job cada `MESH_SYNC_MINUTES` (por defecto
  5) que actualiza/importa PCs en PostgreSQL.
- **UI:** la vista Equipos se refresca cada 30 s sin recargar la página.

## 9. Manejo de errores

- Si el bridge/MeshCentral no responde:
  - se registra el fallo en el log del backend,
  - las filas afectadas se devuelven con `mesh_error: true` y
    `estado: "DESCONOCIDO"`,
  - la UI muestra una advertencia y el estado **Desconocido**.
- Si una PC no existe en MeshCentral:
  - `mesh_encontrado: false`,
  - estado **Desconocido**,
  - no se elimina el registro local.
- El detalle técnico del error no se expone al cliente.

## 12. Interfaz

- **Equipos:** tabla con hostname, MAC, IP, laboratorio, estado, usuario actual,
  último reporte y origen (`MeshCentral`/`Local`); filtro por laboratorio;
  botones **Sincronizar estado** y **Estado** por fila; auto-refresco.
- **Laboratorios:** botón **Sincronizar PCs** para importar/actualizar las PCs
  del laboratorio seleccionado y enlace **Ver equipos**.
- **MeshCentral:** acceso directo desde el menú técnico y desde Equipos.

## 13. Pruebas de aceptación

1. Instalar el agente en una PC Windows y verificar que aparece en MeshCentral.
2. `GET /api/equipment` como Admin Técnico → incluye la PC con `mac_address`,
   `ip_address`, `estado` y `usuario_actual`.
3. `POST /api/equipment/sync` sin laboratorio → importa la PC en el laboratorio
   cuya subred coincide.
4. `POST /api/equipment/sync` con `laboratorio_id` → importa en ese laboratorio.
5. `GET /api/equipment?laboratorio_id=<uuid>` → solo PCs de ese laboratorio.
6. Detener MeshCentral/bridge → `GET /api/equipment` responde con
   `estado=DESCONOCIDO` y `mesh_error=true`.
7. `POST /api/equipment/:id/refresh` con MeshCentral caído → 200 con estado
   Desconocido y sin detalle técnico.
8. Docente lista equipos → solo PCs con sesiones de sus grupos.
9. Sincronización periódica → `ultimo_reporte` se actualiza sin intervención.
10. `auditoria` registra la sincronización como `ACTUALIZAR` con
    `operacion: SINCRONIZAR`, actor, IP y fecha.
