# HU-COM-14 — Autenticación, sesión y control de acceso por roles

**Código:** HU-COM-14  
**Módulo/Épica:** Gestión de Usuarios y Autenticación / Seguridad y RBAC  
**Prioridad:** Must Have  
**Estimación:** 5 SP  
**Estado:** Implementada  
**Fecha:** 2026-11-04

## 1. Objetivo

Permitir que Administradores Académicos, Administradores Técnicos y Docentes
inicien sesión en la plataforma web SGL con sus credenciales de Samba AD,
reciban un JWT con rol y permisos, y accedan únicamente a los módulos
autorizados, con trazabilidad completa de la sesión.

## 2. Alcance

Incluye:

- Login web con validación de campos.
- Validación de credenciales contra Samba AD por **LDAPS**.
- JWT con `uid`, `rol`, `permisos` y `jti`; expiración absoluta configurable.
- Sesión revocable en base de datos (`sesion_web`).
- Expiración por inactividad (backend + frontend).
- RBAC por permisos y matriz de roles.
- Redirección por rol y menú dinámico.
- Denegación 403 + página de acceso denegado.
- Bloqueo temporal tras N intentos fallidos.
- Auditoría de login, logout, fallos, bloqueos y accesos denegados.
- Logout que invalida el token en backend.
- Rechazo de usuarios inactivos, sin rol o con rol no habilitado.

No incluye (pertenece a otras HU):

- CRUD completo de usuarios, grupos, laboratorios, equipos, apps y despliegues.
- Registro automático de sesiones de estudiantes en PCs (`sesion_activa`, RN-020).
- Apertura de KVM/MeshCentral (RN-017 completo).

## 6. Modelo de datos añadido

### `usuario`

- `intentos_fallidos INTEGER NOT NULL DEFAULT 0`
- `bloqueado_hasta TIMESTAMPTZ`
- `ultimo_login TIMESTAMPTZ`

### `sesion_web`

Sesión revocable asociada al `jti` del JWT:

- `jti` único, `usuario_id`, `rol`, `ip_origen`, `user_agent`
- `creada_en`, `ultima_actividad`, `expira_en`
- `revocada_en`, `motivo_revocacion`

### `evento_autenticacion`

Auditoría append-only (triggers bloquean `UPDATE` y `DELETE`):

- `usuario_id` (nullable para intentos con usuario inexistente)
- `uid_intentado`, `rol`, `accion`, `resultado`
- `ip_origen`, `user_agent`, `detalle`, `fecha_evento`

Acciones: `LOGIN`, `LOGOUT`, `LOGIN_FALLIDO`, `LOGIN_BLOQUEADO`,
`USUARIO_INACTIVO`, `SIN_ROL`, `ROL_NO_HABILITADO`, `ACCESO_DENEGADO`,
`SESION_EXPIRADA`, `SESION_REVOCADA`.

## 7. Decisión de seguridad: sesión revocable

Un JWT es stateless. Para cumplir CA-10 (logout invalida el token) y CA-11
(inactividad) se añadió `sesion_web`:

1. El JWT incluye un `jti` único.
2. El middleware busca el `jti` en BD en cada petición.
3. Si la sesión está revocada, expirada o inactiva, responde 401.
4. Logout marca `revocada_en`.

Esto no contradice RN-010: las acciones críticas de negocio siguen usando la
tabla `auditoria`; los eventos de acceso usan `evento_autenticacion`.

## 9. Configuración

Variables en `.env`:

```ini
JWT_EXPIRES=8h
SESSION_IDLE_MINUTES=30
AUTH_MAX_ATTEMPTS=5
AUTH_LOCK_MINUTES=15
LDAP_URL=ldaps://dc.clockwork.local:636
LDAP_BIND_DN=CN=Administrator,CN=Users,DC=clockwork,DC=local
LDAP_BIND_PASSWORD=...
LDAP_SEARCH_BASE=DC=clockwork,DC=local
LDAP_CA_CERT=/app/certs/samba-ca.pem
LDAP_TLS_SERVERNAME=dc.clockwork.local
LDAP_TLS_REJECT_UNAUTHORIZED=true
```

Nginx termina TLS en 443 con certificado autofirmado
(`frontend/certs/sgl.crt` / `sgl.key`). El puerto 8080 sirve HTTP por defecto
para desarrollo local; con `FORCE_HTTPS=true` responde 308 hacia HTTPS. El
bundle puede forzar HTTPS con `VITE_FORCE_HTTPS=true` (build de producción).

## 11. Pruebas de aceptación

1. Login con credenciales válidas de cada rol → JWT y redirección correcta.
2. Login con contraseña inválida → 401 genérico y evento `LOGIN_FALLIDO`.
3. 5 intentos inválidos → bloqueo temporal y evento `LOGIN_BLOQUEADO`.
4. Login de `estudiante` → 403 `ROL_NO_HABILITADO` y evento.
5. Usuario AD válido sin fila en BD → 403 `SIN_ACCESO` y evento `SIN_ROL`.
6. Usuario con `activo = false` → 403 `USUARIO_INACTIVO` y evento.
7. Docente accede a `/api/users` → solo estudiantes de `GRP-1A`.
8. Docente intenta `/api/audit/events` → 403 y evento `ACCESO_DENEGADO`.
9. Admin Académico accede a `/api/audit/events` → 200.
10. Logout → el mismo token devuelve 401 `SESION_REVOCADA`.
11. Sin actividad por `SESSION_IDLE_MINUTES` → 401 `SESION_EXPIRADA`.
12. Ruta frontend sin permiso → redirección a `/403`.
13. Menú lateral muestra solo módulos permitidos por rol.
14. `evento_autenticacion` rechaza `UPDATE`/`DELETE`.
