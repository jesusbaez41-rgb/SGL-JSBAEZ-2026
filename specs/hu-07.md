# HU-COM-07 — Catálogo de aplicaciones e instaladores

**Código:** HU-COM-07  
**Módulo/Épica:** Gestión de Aplicaciones y Despliegue  
**Entorno:** Plataforma Web + Servidor Central (Backend + PostgreSQL)  
**Prioridad:** Must Have  
**Estimación:** 5 SP  
**Estado:** Implementada  
**Fecha:** 2026-11-12

## 1. Objetivo

Permitir que el Administrador Técnico registre programas en un catálogo con
ruta del instalador, parámetros silenciosos, versión y checksum, y los vincule
a laboratorios, de modo que el instalador quede validado por integridad y
preparado para el despliegue remoto.

El instalador puede **subirse desde el navegador** (arrastrando el `.msi` o el
`.exe`): el servidor lo almacena, calcula su SHA-256 y da de alta la
aplicación en un solo paso, sin que el administrador tenga que calcular el
hash ni escribir rutas a mano.

**Como** Administrador Técnico  
**Quiero** registrar programas en un catálogo, subiendo el instalador o
indicando su ruta, con su versión y sus parámetros silenciosos, vinculándolos
a laboratorios  
**Para** disponer de instaladores validados y preparados para el despliegue
remoto.

## 2. Alcance

Incluye:

- CRUD del catálogo de aplicaciones (`aplicacion`).
- Verificación del **SHA-256** del instalador antes de guardarlo (RNF-006).
- **Subida del instalador** desde el navegador con almacenamiento en el
  servidor y cálculo automático del SHA-256.
- **Reemplazo del instalador** de una aplicación existente.
- Re-verificación del checksum bajo demanda y al cambiar ruta/checksum.
- Vinculación app ↔ laboratorio (`vinculo_app_lab`).
- Restricción de una sola versión activa por app y laboratorio (RN-007).
- Desvinculación con conservación del historial (fila `activo = false`).
- Validación reutilizable del vínculo antes de desplegar (RN-002).
- Auditoría de altas, modificaciones, bajas, subidas y vinculaciones (RN-010).
- Pantalla **Aplicaciones** con listado, búsqueda, alta/edición, verificación
  de checksum y gestión de vínculos por laboratorio.

No incluye:

- Ejecución del despliegue remoto ni estado por PC (HU-COM-08).
- Permisos de uso por grupo (`permiso_app_grupo`, RN-008/RN-013).
- Firma digital del instalador; solo se valida el hash SHA-256.
- Distribución de los instaladores a los equipos cliente (eso es HU-COM-08).

## 4. API

| Método | Ruta | Permiso | Descripción |
|---|---|---|---|
| `GET` | `/api/apps` | `apps:read` | Lista el catálogo con cantidad de vínculos activos |
| `GET` | `/api/apps/:id` | `apps:read` | Detalle de la app con sus vínculos |
| `POST` | `/api/apps` | `apps:manage` | Crea una app verificando el checksum de una ruta existente |
| `POST` | `/api/apps/upload` | `apps:manage` | Sube el instalador, calcula el SHA-256 y crea la app |
| `POST` | `/api/apps/:id/installer` | `apps:manage` | Reemplaza el instalador de una app y recalcula el SHA-256 |
| `PATCH` | `/api/apps/:id` | `apps:manage` | Actualiza metadatos y re-verifica si cambia ruta/checksum |
| `DELETE` | `/api/apps/:id` | `apps:manage` | Elimina una app sin vínculos activos |
| `POST` | `/api/apps/:id/verify-checksum` | `apps:manage` | Recalcula el SHA-256 del instalador |
| `GET` | `/api/apps/:id/links` | `apps:read` | Lista los vínculos de la app |
| `POST` | `/api/apps/:id/links` | `apps:manage` | Vincula la app a un laboratorio |
| `DELETE` | `/api/apps/:id/links/:laboratorioId` | `apps:manage` | Desvincula la app del laboratorio |

### Ejemplo de alta por ruta (instalador ya en el servidor)

```json
POST /api/apps
{
  "nombre": "Firefox",
  "version": "128.0",
  "ruta_instalador": "/opt/sgl-instaladores/Firefox-128.0.exe",
  "parametros_silenciosos": "/S /quiet",
  "checksum": "9f2c…64 caracteres hex…"
}
```

Si el archivo no existe o el hash no coincide, la API responde `400` con
`INSTALADOR_NO_ENCONTRADO` o `CHECKSUM_INVALIDO` y **no** guarda la fila.

### Ejemplo de alta por subida (multipart/form-data)

```text
POST /api/apps/upload
Content-Type: multipart/form-data

archivo=@Office-Setup-2024.msi
nombre=Office 365
version=2024.1
parametros_silenciosos=/quiet
```

Respuesta `201`:

```json
{
  "data": {
    "id": "…",
    "nombre": "Office 365",
    "version": "2024.1",
    "ruta_instalador": "/opt/sgl-instaladores/office-365-2024.1.msi",
    "checksum": "0e87375c…",
    "origen": "upload"
  },
  "instalador": {
    "ruta": "/opt/sgl-instaladores/office-365-2024.1.msi",
    "nombre_archivo": "office-365-2024.1.msi",
    "extension": ".msi",
    "tamano": 2048,
    "checksum": "0e87375c…"
  }
}
```

En este flujo **el cliente no envía el checksum**: lo calcula el backend
sobre el archivo almacenado.

### Ejemplo de vinculación

```json
POST /api/apps/<app-id>/links
{
  "laboratorio_id": "<laboratorio-id>"
}
```

Respuestas:

- `201` con el vínculo creado.
- `200` con `created: false` si la misma app ya estaba vinculada (idempotente).
- `409 VERSION_CONFLICTO` si otra versión de la misma app ya está activa en
  el laboratorio (RN-007).

### Códigos de error propios del módulo

| Código | HTTP | Significado |
|---|---|---|
| `CHECKSUM_FORMATO_INVALIDO` | 400 | El checksum no es un SHA-256 hexadecimal de 64 caracteres |
| `INSTALADOR_NO_ACCESIBLE` | 400 | La ruta es remota y no se puede verificar localmente |
| `INSTALADOR_NO_ENCONTRADO` | 400 | No existe el archivo en la ruta indicada |
| `CHECKSUM_INVALIDO` | 400 | El hash calculado difiere del declarado |
| `INSTALADOR_EXTENSION_INVALIDA` | 400 | Extensión de instalador no permitida |
| `INSTALADOR_DEMASIADO_GRANDE` | 413 | El archivo supera `APPS_MAX_UPLOAD_MB` |
| `INSTALADOR_FALTANTE` | 400 | La petición no incluyó archivo |
| `APP_DUPLICADA` | 409 | Ya existe una app con ese nombre y versión |
| `APP_VINCULADA` | 409 | La app tiene vínculos activos |
| `VERSION_CONFLICTO` | 409 | Otra versión de la misma app está activa en el laboratorio |

## 5. Modelo de datos

Se agrega una columna a la tabla existente `aplicacion`
(migración `db/migrations/05-hu07-apps-upload.sql`).

### `aplicacion`

- `id` UUID.
- `nombre` (128, obligatorio).
- `ruta_instalador` (512, obligatorio).
- `parametros_silenciosos` (texto).
- `version` (32, obligatorio).
- `checksum` (128, obligatorio; se normaliza a SHA-256 hexadecimal).
- `origen` (16, `ruta` | `upload`): de dónde sale el instalador.
- `created_at`.

### `vinculo_app_lab`

- `app_id` → `aplicacion.id` (`ON DELETE CASCADE`).
- `laboratorio_id` → `laboratorio.id` (`ON DELETE CASCADE`).
- `activo` (por defecto `TRUE`).
- `fecha_vinculacion`.
- `version` y `app_nombre`: desnormalizados por el trigger
  `tg_vinculo_sync_version`.
- Índice único parcial `ux_vinculo_app_lab_activo`
  (`lower(app_nombre), laboratorio_id WHERE activo`).

## 6. Verificación de integridad

Ubicación: `backend/src/modules/apps/apps.checksum.js`.

1. Se normaliza el checksum (minúsculas, sin prefijo `sha256:`).
2. Se exige el formato `^[a-f0-9]{64}$`; si no, `CHECKSUM_FORMATO_INVALIDO`.
3. Se resuelve la ruta:
   - absoluta → se usa tal cual;
   - relativa → se resuelve contra `APPS_INSTALLERS_DIR`
     (por defecto `/opt/sgl-instaladores`).
4. Se calcula el hash leyendo el archivo por streaming (`crypto.createHash`).
5. Si el archivo no existe o no es un archivo regular:
   `INSTALADOR_NO_ENCONTRADO`.
6. Si el hash calculado difiere del declarado: `CHECKSUM_INVALIDO` con
   `esperado` y `calculado` en el detalle.

La verificación se ejecuta en `create`, en `update` cuando cambia
`ruta_instalador` o `checksum`, y en `POST /:id/verify-checksum`.

En la **subida** no hay checksum declarado: el backend calcula el hash del
archivo almacenado y lo registra, de modo que la app queda verificada por
construcción.

## 7. Subida y almacenamiento de instaladores

Ubicación: `backend/src/modules/apps/apps.upload.js` (transporte) y
`backend/src/modules/apps/apps.storage.js` (almacenamiento).

- El archivo llega como `multipart/form-data` en el campo `archivo`
  (`multer`, almacenamiento en disco temporal).
- **Extensiones permitidas:** `.msi`, `.exe`, `.msix`, `.appx`, `.zip`.
  Cualquier otra devuelve `INSTALADOR_EXTENSION_INVALIDA`.
- **Tamaño máximo:** `APPS_MAX_UPLOAD_MB` (por defecto 1024 MB). Si se excede,
  `INSTALADOR_DEMASIADO_GRANDE`.
- **Nombre final:** `<app>-<version><ext>` con caracteres no alfanuméricos
  reemplazados por `-` (por ejemplo `Office 365` + `2024.1` + `.msi` →
  `office-365-2024.1.msi`). Si el nombre ya existe se agrega un sufijo
  (`-2`, `-3`, …) para nunca sobrescribir un instalador en uso.
- **Destino:** `APPS_INSTALLERS_DIR`, montado en el contenedor del backend.
- **Hash:** se calcula por streaming sobre el archivo ya almacenado.
- **Limpieza:** si el alta falla (nombre duplicado, error de base de datos),
  el archivo subido se borra y no queda huérfano en el servidor.
- **Borrado:** al eliminar una app cuyo `origen` es `upload`, el instalador se
  borra del disco **solo si ninguna otra app lo referencia**.
- El directorio de instaladores debe ser escribible por el usuario del
  backend; el resto del catálogo solo necesita lectura.

## 10. Interfaz

- **Aplicaciones:** listado con nombre, versión, ruta, checksum abreviado,
  cantidad de laboratorios vinculados y acciones.
- **Alta/edición:** modal con una **zona de arrastrar y soltar** el
  instalador. Al soltar el archivo:
  - se muestra nombre, tamaño y el nombre final que tendrá en el servidor;
  - los campos de ruta y checksum se deshabilitan y se explica que el
    hash se calcula en el servidor;
  - el botón pasa a **Subir y registrar**.
- Si no se sube archivo, el formulario conserva el modo manual (ruta +
  checksum) para instaladores que ya están en el servidor.
- **Verificar:** botón que recalcula el hash y muestra el resultado.
- **Vínculos:** modal con los laboratorios disponibles, vínculo activo y
  desvinculación con confirmación.
- Mensajes de éxito/error y estados de carga.
- El menú lateral muestra **Aplicaciones** según el permiso `apps:read`.
