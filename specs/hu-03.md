# HU-COM-03 — Gestión de laboratorios y equipos

**Código:** HU-COM-03  
**Módulo/Épica:** Gestión de Infraestructura / Laboratorios y Equipos  
**Entorno:** Plataforma Web  
**Prioridad:** Must Have  
**Estimación:** 5 SP  
**Estado:** Implementada (CA-06 pendiente de verificación con MeshCentral en vivo)  
**Fecha:** 2026-11-05

## 1. Objetivo

Permitir al Administrador Técnico registrar, editar y listar laboratorios
informáticos, y registrar computadoras vinculando obligatoriamente MAC,
Hostname e IP a un laboratorio, consultando su estado desde MeshCentral.

## 2. Alcance

Incluye:

- CRUD de laboratorios (nombre, ubicación y subred).
- Validación de subred IPv4 en formato CIDR.
- Listado ordenado de laboratorios con cantidad de equipos.
- CRUD de equipos con laboratorio obligatorio (RN-001).
- Unicidad de MAC y hostname.
- Estado del equipo (encendido/apagado), IP actual y usuario con sesión
  activa, consultando MeshCentral.
- Auditoría de altas/modificaciones en `auditoria` (RN-010).

No incluye:

- Despliegue de aplicaciones (HU de despliegues).
- Registro automático de sesiones de PC (HU-COM-01).
- Eliminación física de laboratorios/equipos (no solicitada).
- Gestión de usuarios/grupos (HU-COM-02/HU-COM-14).

## 4. API

| Método | Ruta | Permiso | Descripción |
|---|---|---|---|
| `GET` | `/api/labs` | `labs:read` | Lista laboratorios con cantidad de equipos. |
| `GET` | `/api/labs/:id` | `labs:read` | Consulta un laboratorio. |
| `POST` | `/api/labs` | `labs:manage` | Crea un laboratorio. |
| `PATCH` | `/api/labs/:id` | `labs:manage` | Actualiza nombre, ubicación o subred. |
| `GET` | `/api/equipment` | `equipment:read` | Lista equipos. Docente solo los de sus grupos (RN-017). |
| `GET` | `/api/equipment/:id` | `equipment:read` | Consulta un equipo. |
| `POST` | `/api/equipment` | `equipment:manage` | Registra un equipo con laboratorio obligatorio. |
| `PATCH` | `/api/equipment/:id` | `equipment:manage` | Actualiza MAC, hostname, IP, laboratorio o agente. |
| `POST` | `/api/equipment/sync` | `equipment:manage` | Sincroniza estado/IP de todos los equipos con MeshCentral. |
| `POST` | `/api/equipment/:id/refresh` | `equipment:manage` | Consulta el estado de un equipo en MeshCentral. |

## 5. Modelo de datos

No se agregan tablas: se usan `laboratorio`, `equipo` y `sesion_activa` ya
existentes.

- `laboratorio`: `nombre` único, `ubicacion`, `subred`.
- `equipo`: `mac_address` único, `hostname` único, `ip_address`,
  `laboratorio_id` obligatorio, `estado`, `mesh_agent_id`, `ultimo_reporte`.
- `sesion_activa`: se usa para mostrar el usuario actual cuando no hay dato de
  MeshCentral.

La migración `db/migrations/04-hu03-labs-equipment.sql` agrega el trigger de
validación de subred.

## 6. Interfaz

- **Laboratorios:** listado con nombre, ubicación, subred y cantidad de
  equipos; alta/edición en modal; enlace a equipos filtrados por laboratorio.
- **Equipos:** listado con hostname, MAC, IP, laboratorio, estado, usuario
  actual y último reporte; filtro por laboratorio; alta/edición; botón de
  sincronización con MeshCentral y actualización por equipo.
- El menú técnico incluye un acceso directo a **MeshCentral** (`/mesh/`).

## 7. Integración con MeshCentral

Arquitectura:

```text
Win10 / navegador
   │  http(s)://192.168.100.58:8080/mesh/
   ▼
Nginx (contenedor sgl-frontend)
   │  proxy_pass http://host.docker.internal:4433
   ▼
MeshCentral (servicio systemd en el host, puerto 4433)
   ▲
   │  meshctrl ListDevices
Bridge local (systemd, puerto 4444)
   ▲
   │  GET /devices (x-api-key)
Backend SGL
```

- MeshCentral se publica bajo el dominio `mesh` de su `config.json`.
- Nginx conserva el subpath `/mesh/` y reenvía WebSocket.
- El backend consulta el bridge; si no está disponible, muestra los datos
  locales de PostgreSQL y marca `mesh_source: LOCAL`.
- La sincronización actualiza `estado`, `ip_address`, `ultimo_reporte` y
  `mesh_agent_id`.

## 9. Reglas de negocio

| RN | Impacto |
|---|---|
| RN-001 | `equipo.laboratorio_id` obligatorio y FK `RESTRICT`; la API valida el laboratorio. |
| RN-006 | El estado por PC se consulta y persiste (`estado`, `ultimo_reporte`). |
| RN-010 | Altas/ediciones de laboratorio/equipo y sincronizaciones se auditan. |
| RN-017 | El docente solo ve equipos de sus grupos. |
| RN-018 | MeshCentral es la herramienta de gestión central. |
| RN-019 | En producción la red de laboratorio debe ser Ethernet; el entorno actual usa un puente Wi-Fi (desvío de laboratorio). |

## 10. Pruebas de aceptación

1. Crear laboratorio con subred válida → 201.
2. Subred inválida (`999.1.1.0/24`, `192.168.1.0/33`) → 400/trigger.
3. Listar laboratorios → orden por nombre y conteo de equipos.
4. Crear equipo sin laboratorio → 400.
5. Crear equipo con laboratorio inexistente → 404.
6. MAC duplicada → 409 `MAC_DUPLICADA`.
7. Hostname duplicado → 409 `HOSTNAME_DUPLICADO`.
8. Editar equipo y moverlo de laboratorio → 200.
9. Docente lista equipos → solo equipos con sesiones de sus grupos.
10. Sincronizar MeshCentral → actualiza estado/IP/último reporte.
11. Abrir `/mesh/` → UI de MeshCentral y descarga del agente.
12. Descargar e instalar el agente en Win10 → el equipo aparece en MeshCentral.
13. Verificar que el agente conecta por el subpath `/mesh/`.
